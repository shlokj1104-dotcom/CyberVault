### Key Insight of the Day

**Packet switching wins because it assumes users are bursty, not continuous.**

With 1 Mbps shared link: packet switching handles 35 users (35× circuit switching) because the probability all are active simultaneously is tiny (0.0004). Circuit switching must reserve capacity for each user upfront → wastes idle time. The Internet bet on humans and applications being bursty (web browsing, email, file transfers) rather than steady-state (voice calls). That bet was right — which is why even telephone networks are moving to packet switching. But this also exposes a security weakness: when one user floods the link with packets, everyone else starves (DDoS). Circuit switching would have prevented this by capping traffic upfront.

### Problems I Encountered

#### Confusion #1: Store-and-Forward Delay Formula

**Problem:** Why is it N × (L/R) for N links, not just L/R?  
**Resolution:** The key is that the router must RECEIVE the entire packet before it can START forwarding. So:

- Link 1: Source sends for L/R seconds. At time L/R, router 1 has full packet.
- Router 1 forwards for L/R seconds (from time L/R to 2L/R).
- Router 2 gets packet at 2L/R, can start forwarding.
- And so on...

Each hop adds L/R of delay. With N hops (N links), total = N × (L/R). Without store-and-forward (if bits forwarded immediately), delay would be only L/R + propagation delays.

#### Confusion #2: Packet Switching Efficiency Math

**Problem:** How does 35 users with 0.1 probability work out to only 0.0004 probability of congestion?  
**Resolution:** Binomial probability. With p = 0.1 (user active), n = 35 users:

- P(exactly k active) = C(35,k) × (0.1)^k × (0.9)^(35-k)
- P(11+ active) = sum for k ≥ 11
- Result ≈ 0.0004 (very small)
- So 99.96% of time, ≤10 users active → no queuing.

This is why packet switching is so efficient — it exploits statistical multiplexing. (More details in probability appendix of textbook.)

#### Confusion #3: TDM vs FDM — Which Is Used Where?

**Problem:** Both seem to divide resources. Are they interchangeable?  
**Resolution:** They're fundamentally different:

- **FDM**: Each circuit gets a dedicated frequency band continuously. Used in telephone networks (4 kHz per circuit), FM radio, analog systems.
- **TDM**: Each circuit gets dedicated time slots in every frame. Used in digital telephone networks (8,000 frames/sec × 8 bits/slot = 64 kbps) and modern digital systems.

FDM is inherently analog; TDM is inherently digital. Modern networks use TDM.

#### Confusion #4: Peering vs Customer-Provider Relationship

**Problem:** What's the difference? Both connect ISPs...  
**Resolution:** Critical difference:

- **Customer-Provider:** Access ISP pays Regional ISP. Regional ISP pays Tier-1 ISP. Money flows upstream; traffic can flow both ways.
- **Peering:** ISP A and ISP B are at the SAME level. They directly connect and exchange traffic, SETTLEMENT-FREE. Only makes sense if traffic volume is roughly balanced.
- **Multi-homing:** Different from peering. An access ISP connects to TWO regional ISPs as a customer (pays both) for redundancy.

#### Confusion #5: IXP vs PoP

**Problem:** Both are physical locations. How are they different?  
**Resolution:**

- **PoP (Point of Presence):** Belongs to a single ISP. Customer ISPs lease a link to connect there. It's the provider's building.
- **IXP (Internet Exchange Point):** Independent, third-party facility. Multiple ISPs own switches there. ISPs peer with many other ISPs at the same IXP location. Cheaper than building separate PoPs.

Analogy: PoP = your personal office; IXP = shared coworking space where you meet multiple people at once.

#### Confusion #6: Why Does Circuit Switching Establish a Connection?

**Problem:** Why does circuit switching need that setup phase?  
**Resolution:** In circuit switching, resources are RESERVED along the path. The network must:

1. Find a path from source to destination
2. Check if the same frequency band (FDM) or time slot (TDM) is free on ALL links in the path
3. Lock/reserve those resources across all switches and links
4. Only then is the connection "established"

This is why circuit switching is slow to set up but guarantees constant rate. Packet switching skips all this — just send packets immediately (best effort).

### Security Angles Identified (Networking)

1. **DDoS via packet flooding:** Attacker floods output buffers → packet loss for legitimate users. Defense: rate limiting, traffic shaping.
2. **BGP hijacking:** Attacker poisons routing tables → traffic redirected to attacker. Defense: RPKI, BGP monitoring.
3. **Man-in-the-middle at IXP:** Attacker at IXP location monitors traffic passing through switches. Defense: encrypt end-to-end (TLS/IPSec).
4. **Content provider network compromise:** If Google's private network is breached, millions of users affected. Defense: Google's internal security.
5. **Timing side-channels:** Attacker exploits variable queuing delays to infer network state. Defense: randomized packet scheduling + jitter.

    **Style 3: Default Values** (25 min)
    
    - Set default in function definition: `def describe_pet(pet_name, animal_type='dog'):`

    - Python error message names the missing arguments — read it; don't guess
    - Error occurs at CALL site, not definition

    - Same validation logic reused every loop iteration
    - Real-world: user registration, search, menus all follow this pattern

    - When you pass a list, function gets DIRECT ACCESS to it; changes are PERMANENT

### Key Insight of the Day

**Functions are about DRY (Don't Repeat Yourself) and separation of concerns.**

When you write `get_formatted_name()` once, you can call it 1,000 times from different parts of your program. Change the formatting rule? Modify one function, not 1,000 call sites. Modules extend this: group related functions into `.py` files, reuse across projects, share with teammates without exposing implementation.

For FitHub: `calculate_fitness_score()` lives in one function. When you discover a better formula, update that function, and every dashboard automatically shows the new value.

### Problems I Encountered

#### Confusion #1: Order of Parameters with Defaults

**Problem:** Why can't I put default parameters before required ones?  
**Resolution:** Python reads left-to-right. When you call `f('harry')`, it can't tell if you're overriding the default or passing the second parameter. Enforce: **all required parameters first, then optional ones.**

#### Confusion #2: Lists Are Passed by Reference, Not Value

**Problem:** Why does modifying a list inside a function change the original?  
**Resolution:** Lists are mutable and passed by reference — you're passing a pointer to the SAME list in memory. `.pop()` and `.append()` modify that shared list. Pass `list[:]` to preserve the original.

#### Confusion #3: `*args` Creates a Tuple, Not a List

**Problem:** What data type is `*args`?  
**Resolution:** A **tuple** — immutable. This prevents accidental mutation. For `for` loops, tuples and lists behave identically. Convert with `list(toppings)` if you need to modify.

#### Confusion #4: Default Arguments Are Evaluated Once, at Definition Time

**Problem:** Why does `def f(target=[]):` accumulate values across calls?  
**Resolution:** The default `[]` is evaluated ONCE at definition — all calls share the same list. Fix: use `None` as default and create a fresh list inside:

```python
def append_to(element, target=None):
    if target is None:
        target = []
    target.append(element)
    return target
```

Always use immutable defaults (`None`, strings, numbers).

#### Confusion #5: Return Values Can Be Missing (Implicit `None`)

**Problem:** What happens if a function has no `return` statement?  
**Resolution:** Python implicitly returns `None`. Assign `result = greet('Alice')` and `result` is `None` (falsy). If a function should return a value, always include an explicit `return`.

#### Confusion #6: `**kwargs` Parameter Name Can Be Anything

**Resolution:** The `**` prefix is what matters. `kwargs` is just convention. You could write `**options` or `**settings`. Use `**kwargs` for consistency.

#### Confusion #7: Module Alias Doesn't Rename the Module

**Problem:** After `import pizza as p`, does `pizza.make_pizza()` still work?  
**Resolution:** Alias creates a LOCAL NAME. Trying `pizza.make_pizza()` raises `NameError`. Use the alias consistently throughout your file.

#### Confusion #8: When to Use `*args` vs. Multiple Parameters

**Resolution:** Use `*args` when the caller might pass any number of items (variable count). Use fixed parameters when the function always needs exactly that many arguments and names clarify intent.

### Security Angles Identified (Python)

1. **Code injection via `eval()`:** Never `eval()` user input. Whitelist allowed functions instead.
2. **Mutable default arguments as hidden global state:** Shared state across calls can be exploited. Use `None` default.
3. **Information disclosure via docstrings:** Keep docstrings vague in production; avoid naming sensitive logic.
4. **Module import hijacking:** Never insert untrusted paths into `sys.path`. Use virtual environments.
5. **Denial of Service via recursion:** Validate input ranges; prefer iterative approaches for untrusted input.
6. **Pickle deserialization:** Use `json` for untrusted data; only `pickle` for trusted sources.
